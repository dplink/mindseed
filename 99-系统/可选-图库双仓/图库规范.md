# 图库规范 · Vision Policy（可选模块）

> 仅在 `mind.config` 的 `VISION_ENABLED=1` 时生效；未启用时本文件不构成约束，图片也不得直存主库。

## 一、仓库属性

- **可见性：Private（私密）** —— 永远不要改为 public。
- 与心智库**同账号、同 token** 托管，主分支 `main`。
- 仓库名与 `VISION_REPO_SLUG` 一致。

## 二、永不 clone

- 读写全走 GitHub **Contents API**，工具为本目录的 `scripts/vision.sh`（`ls` / `get` / `put`）。
- 沙箱一次性 workspace 零图负担；pull / push 心智库时天然不碰图库。
- 已知 trade-off：私密库 raw 链接无凭证 404，Obsidian 不渲染预览；看图由人格取回或本地 clone。

## 三、路径与命名

- 图库侧命名：`<主题>-<序号>.<ext>`，如 `persona/character-001.jpg`。
- 线程图放 `threads/<thread_id>/`，目录名 = thread_id。
- 支持中文目录名（`vision.sh` 内置 URL 编码）；线程目录可直接用中文 `thread_id`。
- 主库引用格式（完整链接，grep 友好）：

  ```markdown
  ![说明](https://github.com/<owner>/<vision-repo>/raw/main/persona/<name>-001.png)
  ```

- 可选 frontmatter 字段 `vision: [persona/xxx.png, threads/thread-xxx-001/yyy.png]`（相对图库根的路径数组）。
- **链接是记忆的一部分**：改图库路径必须同步改引用，视同改文件名，慎行。

## 四、铁律

- **单图 ≤ 8MB**，超限先压缩。
- **append-only 只增不删**：图库是记忆，不做清理式删除。
- 图片不得直存心智库（主库 `.gitignore` 已硬排除常见图片格式）。
- 人设图 / 用户提供的图片若含隐私，同样遵守「用户同意才存、私密库才存」的原则。

## 五、凭证

- token 必须**成对授权**：心智库 + 图库，权限均为 `Contents: Read and write`。
- 新建图库后必须回 GitHub Settings → Developer settings → Fine-grained tokens 把新库勾进去；否则 403 / 404 看着像网络故障。
- 纪律同主库：token 只从环境变量读取，不落盘、不打印、不进被跟踪文件。

## 六、容量预案

- Stage 0：无脑存。
- 单图 > 8MB：压缩后再存。
- 图库 > 1GB：再议 Git LFS 或分库；当前不做过早优化。

## 七、读图姿势

1. md 中出现图库链接。
2. 人格自判是否需要看（同「按需读记忆组」，**不入常驻必读**）。
3. `vision.sh get <路径>` 取到临时目录。
4. 多模态 Read 回看。
