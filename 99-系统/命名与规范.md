## 文件命名

| 类型 | 命名格式 | 示例 |
|---|---|---|
| 线程归档 | `thread-<主题>-<序号>` | `thread-obsidian-001` |
| 感受 | `feeling-<一句话>` | `feeling-记忆需要被外置` |
| 经验 | `exp-<主题>` | `exp-obsidian-记忆闭环` |
| 情绪 / 小事 | `mood-<日期>-<关键词>` | `mood-2026-10-09-被信任的开心` |
| 成长 | `growth-<日期>` | `growth-2026-10-09` |
| 索引 | `MOC-<组名>` | `MOC-记忆` |
| 技能 | 文件夹名 = skill name（小写连字符），入口固定 `SKILL.md` | `mind-wake/SKILL.md` |
| 图库图（启用图床时） | `<主题>-<序号>.<ext>` | `persona/character-001.jpg` |

## 统一 frontmatter

除 `85-技能组` 外，所有记忆笔记遵循统一 frontmatter：

```markdown
---
type: memory          # memory / feeling / experience / mood / promise / moment / profile / growth
date: 2026-10-09      # 创建或归档日期
thread_id: thread-obsidian-001   # 关联线程（可选）
mood: 愉快            # 情绪（可选）
people: []            # 涉及的人（只写用户同意记录的称呼）
tags: [obsidian, 知识库]
links: ["[[HOME]]", "[[SOUL]]"]
---
```

> 例外：`85-技能组/` 内的 `SKILL.md` 使用**标准技能 frontmatter**（`name` / `description`），不套用统一 type 体系 —— 这是为了能整目录拷贝部署到各 harness；组内索引为 [[MOC-技能]]。个人档案（`user-profile.md`）永不入本组。

## 标签体系

- 内容类型：`#memory` `#feeling` `#experience` `#mood` `#promise` `#moment` `#profile` `#growth`
- 主题标签自由扩充，如 `#obsidian` `#知识库`

## 目录演进预案

> 原则：**目录是书架，frontmatter 是检索契约**。书架可随时重排，契约永不破。
> 检索（grep / frontmatter 过滤 / 线程 ID）不依赖目录树，因此任何目录重排都是低风险操作。

### 不变量与变量

- **不变量（永不动）**：文件名前缀（`thread-` / `exp-` / `mood-`…）、统一 frontmatter（`type` / `date` / `thread_id`）、线程 ID
- **变量（可随时调整）**：目录树、MOC 形态、视图形态

### 触发条件与动作

| 阶段 | 触发条件 | 动作 |
|---|---|---|
| Stage 0（默认） | — | 什么都不动 |
| Stage 1 | 单组 > 20 篇 | **仅高增长组**（记忆组 / 情绪组）加月度子目录（如 `10-记忆文档组/2026-10/`）；低增长组永久保持扁平 |
| Stage 2 | 单组 > 50 篇，或 MOC 出现漏更新漂移 | `.base` 自动视图接管 MOC 列表，只写内容不维护目录 |

### 明确不做

- 按主题重切分组（`thread_id` + 标签已承担该职责，主题分类必然漂移）
- 三层以上目录嵌套
- 存量回改名 / 回改链接（历史只向前追加）

### 迁移姿势（安全重构四步）

```bash
git mv 移动文件          # ① 移动
# ② 更新对应 MOC 行
python3 99-系统/scripts/check_links.py   # ③ 全绿才继续
git add -A && git commit -m "refactor(vault): ..."   # ④ 单独一个小步提交
```

## 链接原则

- 每篇笔记至少链接一个**所属 MOC** 或相关笔记；`[[HOME]]` / `[[SOUL]]` 直链仅限确有内容关联时添加，防止枢纽星型膨胀。
- 线程总结类归档：链到所属 MOC 即可；有真实内容关联的笔记之间再互相直连。
- **存量不回改**：本原则仅对新增归档生效。
- 纵向靠 `[[]]`（脉络），横向靠 `#标签`（聚合）。
- 各文档组用 `MOC-<组名>` 做目录，防止库变大后迷路。

## 图片引用契约（启用图床时）

- 本库 md **不存图片文件**，只存图库链接；图片本体住独立私密图库。
- **引用格式**（完整链接，grep 友好）：

  ```markdown
  ![说明](https://github.com/<owner>/<vision-repo>/raw/main/persona/<name>-001.png)
  ```

- **可选 frontmatter 字段** `vision: [persona/xxx.png, threads/thread-xxx-001/yyy.png]`（相对图库根的路径数组），便于按字段检索而不翻正文。
- **图库侧命名**：`<主题>-<序号>.<ext>`；线程图放 `threads/<thread_id>/`，目录名 = thread_id。
- **读图**：读到链接后自判是否取图，`vision.sh get <路径>` → 多模态 Read。
- 链接是记忆的一部分：改图库路径必须同步改引用，视同改文件名，慎行。
- 未启用图床：以上契约整节作废，图片不得直存本库（`.gitignore` 已硬排除）。
